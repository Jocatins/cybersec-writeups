CTF Write-up: Double Vision

Challenge Description

An image appeared completely normal, but the challenge hinted that additional information was hidden inside the file. The objectives were to inspect the file, identify embedded data, extract hidden content, and recover the flag.

Tools Used

  • file
  • binwalk
  • dd
  • xdg-open

Step 1 - Identify the File

First, determine the actual file type.

file Challenge.jpg

Output:

Challenge.jpg: JPEG image data, JFIF standard 1.02,
resolution 72x72,
5184 x 3456,
components 3

The file appeared to be a perfectly normal JPEG image.

Step 2 - Check File Size

Inspect the file size.

ls -lh Challenge.jpg

Output:

-rw-rw-r-- 1 kali kali 1.5M Challenge.jpg

Nothing unusual was immediately apparent.

Step 3 - Scan for Embedded Files

Since the challenge hinted that data might be hidden inside the image, the next step was to inspect the binary structure using binwalk. 

binwalk Challenge.jpg

Output:

DECIMAL       HEXADECIMAL     DESCRIPTION
--------------------------------------------------------------
0             0x0             JPEG image
382           Copyright string
211234        JBOOT STAG header
1529267       PNG image, 895 x 237
1529358       Zlib compressed data

The important discovery was that a complete PNG image was embedded near the end of the JPEG.

Observation:
The detected JBOOT header was likely a false positive. The embedded PNG was the real target.

Step 4 - Attempt Automatic Extraction

binwalk -e Challenge.jpg

Result:

WARNING:
One or more files failed to extract.

Binwalk detected the hidden data but could not automatically extract it. Manual extraction was required.

Step 5 - Manually Carve the Embedded PNG

Binwalk reported that the PNG started at offset 1529267. Using dd, the embedded image was extracted. 

dd if=Challenge.jpg of=hidden.png bs=1 skip=1529267

Step 6 - Verify the Extracted File

file hidden.png

Output:

hidden.png:
PNG image data,
895 x 237,
8-bit/color RGBA,
non-interlaced

The extracted file was confirmed to be a valid PNG image.

Step 7 - Open the Hidden Image

The extracted image was opened using the system image viewer. 

xdg-open hidden.png

Success!

The hidden PNG displayed the challenge flag directly. No additional steganography or decoding was required.

Lessons Learned

  • Files can contain multiple embedded file formats.
  • A JPEG may have another complete file appended to its end.
  • Binwalk is excellent for identifying embedded file signatures.
  • If automatic extraction fails, manually carve files using dd.
  • Always verify extracted files with the file command.
  • Sometimes the hidden file simply needs to be opened to reveal the flag.

Key Commands Used

file Challenge.jpg

ls -lh Challenge.jpg

binwalk Challenge.jpg

binwalk -e Challenge.jpg

dd if=Challenge.jpg of=hidden.png bs=1 skip=1529267

file hidden.png

xdg-open hidden.png

Conclusion

The challenge demonstrated a classic digital forensics technique where one file is embedded inside another. Although the JPEG appeared ordinary, binary analysis revealed an appended PNG image. After manually extracting the PNG using the offset identified by Binwalk, opening the image immediately revealed the flag. This exercise reinforced the importance of performing thorough forensic enumeration rather than trusting a file solely based on its extension or appearance.
