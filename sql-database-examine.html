SQL Injection: Examining the Database

This PortSwigger Web Security Academy lab contained a SQL injection vulnerability in the product category filter. The objective was to use a UNION attack to retrieve and display the database version.

1. Understanding the Objective

When exploiting SQL injection, it is often necessary to learn about the database behind the application. Useful information includes:

  • The type and version of the database software.
  • The tables contained in the database.
  • The columns contained in those tables.

In this lab, the hint indicated that the database was Oracle. Oracle also requires a table in a SELECT statement, so the built-in dual table was used for the initial UNION test.

2. Confirming the Number of Columns

The first step was to determine how many columns the original query returned and whether those columns could contain text.

'+UNION+SELECT+'abc','def'+FROM+dual--

This is logically equivalent to:

' UNION SELECT 'abc','def' FROM dual--

The application returned:

<th>abc</th>
<td>def</td>
Result: The UNION attack worked. This confirmed that the original query returned two columns, and both columns were compatible with text data.

3. Retrieving the Oracle Version

Oracle provides version information through the v$version view, with the version text available in the BANNER column. 

'+UNION+SELECT+BANNER,+NULL+FROM+v$version--

This is logically equivalent to:

' UNION SELECT BANNER, NULL FROM v$version--

BANNER was placed in the first column because that is where the database information should appear. NULL was used for the second column to satisfy the two-column requirement discovered during testing.

4. Result

CORE  11.2.0.2.0  Production
NLSRTL Version 11.2.0.2.0 - Production
Oracle Database 11g Express Edition Release 11.2.0.2.0 - 64bit Production
PL/SQL Release 11.2.0.2.0 - Production
TNS for Linux: Version 11.2.0.2.0 - Production

The important result was:

Oracle Database 11g Express Edition Release 11.2.0.2.0 - 64bit Production
Lab solved: The Oracle database version was successfully retrieved using a UNION-based SQL injection.

5. Querying Database Type and Version

The database type and version can potentially be identified by trying provider-specific queries and observing which one works.

Database typeVersion query
Microsoft / MySQLSELECT @@version
OracleSELECT * FROM v$version
PostgreSQLSELECT version()

For example:

' UNION SELECT @@version--

A response such as the following identifies Microsoft SQL Server and its version:

Microsoft SQL Server 2016 (SP2) (KB4052908) - 13.0.5026.0 (X64)
Mar 18 2018 09:11:49
Copyright (c) Microsoft Corporation
Standard Edition (64-bit) on Windows Server 2016 Standard 10.0

6. What I Learned

  • SQL injection can be used to investigate the underlying database.
  • A UNION attack requires the correct number of columns.
  • The returned columns must have compatible data types.
  • Oracle uses dual when a SELECT statement needs a FROM source.
  • Oracle exposes version information through v$version.
  • Database-specific syntax matters when testing SQL injection.
Core lesson: The process was: identify the injection point → determine the column count → confirm compatible data → identify the database → query the appropriate version information.
