SQL Injection UNION Attack — Retrieving Usernames and Passwords

Lab Overview

This PortSwigger Web Security Academy lab contained a SQL injection vulnerability in the product category filter.

The application's database contained a separate users table with the following columns:

  • username
  • password

The objective was to perform a SQL injection UNION attack to retrieve all usernames and passwords and then use the credentials to log in as the administrator user.

Objective

The goal was to exploit the vulnerable category parameter and use a UNION SELECT statement to retrieve information from the users table.

Understanding the UNION Attack

A SQL UNION operation allows the results of two SELECT statements to be combined.

For a UNION attack to work, the injected SELECT statement generally needs to return the same number of columns as the original query. The data types must also be compatible with the corresponding columns.

Key lesson: Before attempting to extract useful information, determine the number of columns returned by the original query and identify which columns are reflected in the application's response.

Step 1 — Testing the Number of Columns

I first tested the vulnerable category parameter using UNION SELECT statements containing NULL values.

The following payload successfully returned results: 

GET /filter?category=Pets'+UNION+SELECT+NULL,password+FROM+users-- HTTP/2

I also tested: 

GET /filter?category=Pets'+UNION+SELECT+NULL,username+FROM+users-- HTTP/2

Both requests returned results.

This demonstrated that the injected UNION query was being interpreted successfully with two columns.

Column Test Result
1 NULL Accepted
2 username / password Displayed

Step 2 — Retrieving Usernames

I used the following payload to retrieve usernames from the users table: 

GET /filter?category=Pets'+UNION+SELECT+NULL,username+FROM+users-- HTTP/2

The application returned usernames from the database.

Step 3 — Retrieving Passwords

I then tested the password column: 

GET /filter?category=Pets'+UNION+SELECT+NULL,password+FROM+users-- HTTP/2

This also returned results containing passwords.

Problem: Although both queries worked, the usernames and passwords appeared in separate responses. This made it difficult to determine which password belonged to which username.

Step 4 — Combining Username and Password

Instead of retrieving the two columns separately, I combined the username and password values into a single output column.

The final successful payload was: 

GET /filter?category=Pets'+UNION+SELECT+NULL,username||':'||password+FROM+users-- HTTP/2

The || operator was used to concatenate the username, a colon separator, and the password.

Conceptually, the injected query was: 

SELECT NULL, username || ':' || password
```

Instead of returning the values separately, the application therefore displayed them in the following format:

Success: The final UNION payload displayed each username alongside its corresponding password, making it possible to identify the administrator credentials.

Step 5 — Logging in as Administrator

After identifying the credentials associated with the administrator username, I used those credentials on the application's login page.

The login was successful, completing the lab.

Final Payload

GET /filter?category=Pets'+UNION+SELECT+NULL,username||':'||password+FROM+users-- HTTP/2

Attack Flow

  1. Identify the vulnerable category parameter.
  2. Determine the number of columns accepted by the UNION query.
  3. Confirm that the query returned two columns.
  4. Retrieve usernames from the users table.
  5. Retrieve passwords from the users table.
  6. Recognize that separate responses made credential matching difficult.
  7. Concatenate username and password into one column.
  8. Identify the administrator credentials.
  9. Log in as administrator and complete the lab.

Key Lessons Learned

  • UNION attacks require careful consideration of the number of columns returned by the original query.
  • NULL values are useful when determining a compatible UNION structure.
  • Identifying which column is reflected in the application's response is important for extracting useful data.
  • SQL queries can sometimes concatenate multiple database values into a single output column.
  • Extracting usernames and passwords separately can make it difficult to establish which credentials belong together.
  • Combining related values into one response can make database enumeration much easier.

Final Takeaway

This lab reinforced the practical process behind a SQL injection UNION attack. Rather than simply memorizing payloads, the important part was understanding the reasoning behind each step: determine the column count, identify the reflected column, retrieve data from the target table, and finally structure the output so related information can be interpreted correctly.

The most important payload from this exercise was: 

' UNION SELECT NULL,username||':'||password FROM users--

This allowed the application to return each username together with its corresponding password in a single response.
