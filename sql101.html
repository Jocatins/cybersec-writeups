SQL 101 — Authentication Bypass

Sacred Heart Medical Center CTF Challenge Writeup

🎯 Objective

The objective was to bypass the hospital EHR login system and retrieve a hidden flag using SQL Injection techniques.

🧠 Vulnerability

The application directly concatenated user input into SQL queries without sanitization or parameterization.

SELECT * FROM users WHERE username = '<USERNAME>' AND password = '<PASSWORD>';
Root Cause: User input was interpreted as SQL code, allowing attackers to manipulate query logic.

💥 Exploitation Strategy

  • Break out of the SQL string using a quote (')
  • Inject an always-true condition
  • Comment out the remaining query
  • Force authentication logic to return TRUE

🚀 Working Payload

' OR 1=1 --

Generated Query

SELECT * FROM users WHERE username = '' OR 1=1 -- ' AND password = 'anything';
Result: Authentication bypass successful and flag retrieved.

⚠️ Why These Work

These payloads exploit applications that embed user input directly into SQL queries.

Key Techniques:
  • Breaking string context with quotes
  • Injecting Boolean logic
  • Commenting out remaining SQL
  • Forcing conditions to evaluate TRUE

🧾 Key Takeaways

  • Never trust raw user input in SQL queries.
  • Use prepared statements and parameterized queries.
  • Avoid string concatenation for authentication logic.
  • SQL Injection remains one of the most common vulnerabilities.
  • Validate and sanitize user input.
  • Implement least privilege database access.
