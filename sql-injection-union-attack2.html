SQL Injection UNION Attack — Finding a Column Containing Text

Lab Overview

Platform: PortSwigger Web Security Academy

Lab: SQL injection UNION attack, finding a column containing text

Difficulty: Practitioner

Status: Solved

This lab contained a SQL injection vulnerability in the product category filter. The application returned the results of the underlying SQL query directly in the HTTP response, making it possible to use a UNION SELECT attack to introduce additional data into the response.

Objective

The objective was to determine which column returned by the vulnerable SQL query was compatible with string data and then use that column to make the lab-provided value appear in the application's response.

The lab provided the following value: 

F8bikY

Initial Analysis

The vulnerable parameter was the category parameter on the /filter endpoint.

The request structure was: 

GET /filter?category=Tech+gifts

Since this was a UNION-based SQL injection lab, the first step was to determine the number of columns returned by the original query.

Step 1 — Determine the Number of Columns

I tested different numbers of NULL values using UNION SELECT.

The important observation was that attempts using the wrong number of columns resulted in an HTTP 500 response.

I eventually tested a UNION query containing three columns: 

' UNION SELECT NULL,NULL,NULL--

This established that the original query was returning three columns.

Column Test Value
1 NULL
2 NULL
3 NULL

Step 2 — Identify the String-Compatible Column

Knowing that the query returned three columns, I needed to determine which column could contain string data.

I tested a string in the second column while keeping the remaining columns as NULL: 

' UNION SELECT NULL,'test',NULL--

The complete request sent through Burp Repeater was: 

GET /filter?category=Tech+gifts' UNION SELECT NULL,'test',NULL-- HTTP/2

The server responded with: 

HTTP/2 200 OK

More importantly, the application displayed the injected value in the response: 

<tr>
<th>test</th>

Finding: The second column is compatible with string data.

Step 3 — Insert the Required Lab Value

The lab instructed me to make the following value appear in the query results: 

F8bikY

Since the second column had already been confirmed to accept strings, I replaced test with the required value. 

' UNION SELECT NULL,'F8bikY',NULL--

The final HTTP request was: 

GET /filter?category=Tech+gifts' UNION SELECT NULL,'F8bikY',NULL-- HTTP/2

Why the Final Payload Worked

The successful injection can be broken down into several parts: 

' UNION SELECT NULL,'F8bikY',NULL--
  • ' closes the string value used by the original SQL query.
  • UNION SELECT adds the results of another SELECT statement to the original query.
  • The three values correspond to the three columns returned by the original query.
  • F8bikY is placed in the second column because that column was confirmed to support string data.
  • NULL is used for the other two columns because their specific data types were not required for this test.
  • -- comments out the remainder of the original SQL statement.

Attack Flow

  1. Identify the vulnerable category parameter.
  2. Determine the number of columns returned by the original query.
  3. Confirm that the query returns three columns.
  4. Place a test string in each column until a string-compatible column is found.
  5. Confirm that the second column accepts string data.
  6. Replace the test string with the lab-provided value F8bikY.
  7. Verify that the value appears in the application's response.
  8. The lab was successfully solved.

Key Lessons Learned

  • A UNION attack requires the injected SELECT statement to have the same number of columns as the original query.
  • NULL values are useful when determining the number of columns because they can be compatible with many SQL data types.
  • Finding the number of columns is only part of constructing a UNION attack. You may also need to determine which columns accept particular data types.
  • A successful HTTP response does not necessarily mean the lab is solved. The injected data must actually appear in the expected location or satisfy the lab's objective.
  • Burp Suite Repeater is useful for systematically testing SQL injection payloads and comparing server responses.
