CTF Write-up: Reused OTP

Challenge Overview

This challenge demonstrates one of the most famous failures in cryptography: reusing a One-Time Pad (OTP) key. Although the One-Time Pad is theoretically unbreakable, it becomes completely insecure once the same key is used more than once.

Challenge Information

Ciphertext 1

5e984e3eb6c1be7734ca7ddd3c

Ciphertext 2

4cc41231bde1b17710a359f539

Known Plaintext

send_help_now
The analyst had already recovered the plaintext of Message 2 but failed to realize that the same OTP key had been reused.

Understanding the Mathematics

For a One-Time Pad, 
Ciphertext = Plaintext XOR Key
Therefore, 
C = M XOR K
Since Message 2 is known, 
K = C2 XOR M2
Once the key is recovered, 
M1 = C1 XOR K
This completely reveals the first message.

Step 1 - Recover the Key

We XOR the second ciphertext with the known plaintext. 
Key = Ciphertext2 XOR "send_help_now"
Recovered key: 
3fa17c55e289d41b60fc379a4e

Step 2 - Decrypt Message 1

Using the recovered key, 
Message1 = Ciphertext1 XOR Key
Recovered plaintext: 
a92kTHllT6JGr

Python Script Used

from binascii import unhexlify

c1 = unhexlify("5e984e3eb6c1be7734ca7ddd3c")
c2 = unhexlify("4cc41231bde1b17710a359f539")

known_plaintext = b"send_help_now"

key = bytes(c ^ p for c, p in zip(c2, known_plaintext))

flag = bytes(c ^ k for c, k in zip(c1, key))

print("Recovered Key:", key.hex())
print("Recovered Message:", flag.decode())

Why This Works

A One-Time Pad is mathematically secure only if:
  • The key is completely random.
  • The key is at least as long as the message.
  • The key is never reused.
  • The key remains secret.
When the same key encrypts multiple messages, 
C1 = M1 XOR K

C2 = M2 XOR K
An attacker can compute 
C1 XOR C2

= (M1 XOR K) XOR (M2 XOR K)

= M1 XOR M2
because 
K XOR K = 0
If one plaintext is known (or even partially guessed), the key can be recovered, allowing every other message encrypted with that key to be decrypted.

Real-World Relevance

1. Venona Project

The most famous real-world example occurred during the Cold War. Soviet intelligence accidentally reused One-Time Pad keys. American cryptanalysts exploited the reuse and successfully decrypted thousands of classified Soviet communications. This operation became known as the Venona Project.

2. Stream Cipher Nonce Reuse

Modern stream ciphers such as ChaCha20 and AES-CTR generate a keystream that behaves like a One-Time Pad. Reusing the same key and nonce produces the same keystream, creating exactly the same vulnerability as OTP key reuse. This is why modern cryptographic libraries enforce unique nonces.

3. Malware and Ransomware

Poorly written malware sometimes encrypts files using identical XOR keys or reused keystreams. Digital forensic investigators can recover encryption keys and restore files without paying the ransom.

4. Wireless Communications

Historical weaknesses in protocols such as WEP stemmed from IV (Initialization Vector) reuse. Repeated keystreams enabled attackers to recover network traffic and encryption keys, leading to the protocol's eventual replacement by WPA and WPA2.

Key Takeaways

  • A One-Time Pad is only secure when every key is used exactly once.
  • Reusing an OTP key destroys its perfect secrecy.
  • Known-plaintext attacks become possible whenever one encrypted message is known.
  • XOR is reversible: 
    A XOR B XOR B = A
    This property allows recovery of keys and plaintexts.
  • Modern encryption systems rely heavily on proper key and nonce management.
  • Many real-world cryptographic failures are caused by implementation mistakes rather than weaknesses in the underlying algorithms.
  • Reading challenge descriptions carefully is essential—critical clues are often hidden in analyst notes, comments, or metadata.

Conclusion

This challenge highlights an important lesson in applied cryptography: security depends not only on strong algorithms but also on correct implementation. The One-Time Pad remains theoretically unbreakable, yet a single operational mistake— reusing the encryption key—completely undermines its security.
