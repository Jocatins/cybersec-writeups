Header Hijack – CTF Write-up

Challenge Summary

The objective was to access an administrator page that returned Access Denied. The hint suggested inspecting the request and modifying HTTP headers using Burp Suite.

Our Investigation

  1. Created an account and logged in.
  2. Intercepted the request to the admin page with Burp Suite.
  3. Observed the HTML response contained a hidden developer comment: 
    <!-- Tip: Check the request headers for the admin access key. -->
  4. Reviewed the HTML and noticed it loaded: 
    /challenge_7/js/admin.js
  5. Opened the JavaScript file directly in the browser.
  6. The JavaScript revealed the information required for the challenge, ultimately leading to the flag.

Why Inspect admin.js?

Modern web applications place much of their logic in JavaScript. Whenever an HTML page loads a script related to authentication, administration, or API calls, that file becomes a high-value target.

  • JavaScript frequently contains API endpoints.
  • Developers sometimes hardcode custom header names.
  • Configuration values, feature flags, tokens, or test secrets may be accidentally exposed.
  • The code often shows exactly how requests are constructed.

General Methodology for Similar Challenges

  • Inspect every request and response.
  • Read HTML comments—they often contain clues.
  • Open every linked JavaScript file.
  • Search JavaScript for terms such as fetch, headers, X-, Authorization, token, admin, secret, and key.
  • Use Burp Repeater to modify requests and compare responses.
  • Never assume client-side code is harmless; treat it as documentation of the application's behavior.

Real-World Applications

  • Penetration Testing: Identify exposed API keys, debug endpoints, or insecure authorization checks.
  • Bug Bounty Hunting: Discover information leakage through JavaScript bundles.
  • Secure Code Reviews: Verify sensitive data is never shipped to browsers.
  • Incident Response: Understand how a compromised web application communicates with backend APIs.
  • Web Development: Learn why secrets must remain on the server and why authorization should never rely solely on client-controlled headers.

Key Takeaways

  • Follow the clues left by the application.
  • Inspect JavaScript whenever a page loads it.
  • Understand that HTTP headers are user-controlled unless validated server-side.
  • Small observations, such as HTML comments, often unlock an entire challenge.
