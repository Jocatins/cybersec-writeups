SQL Injection UNION Attack — Retrieving Multiple Values in a Single Column

Lab Overview

Lab SQL injection UNION attack, retrieving multiple values in a single column
Difficulty Practitioner
Vulnerability SQL Injection — UNION-based SQL Injection
Target Product category filter
Objective Retrieve usernames and passwords from the users table and use the administrator credentials to log in.

1. Lab Objective

The application contains a SQL injection vulnerability in the product category filter. The results of the underlying SQL query are reflected in the application's response.

The database contains a separate users table with the following columns:

  • username
  • password

The challenge was to perform a UNION-based SQL injection attack that retrieves both values even though only a single output column is available for displaying arbitrary text.

2. Identifying the Number of Columns

The first step was to determine how many columns were being returned by the original SQL query.

A UNION query must contain the same number of columns as the original query. From previous testing, the query was determined to return two columns.

The next step was therefore to determine which column could display text.

3. Testing a Text-Compatible Column

I injected a simple string into the second column: 

GET /filter?category=Pets'+UNION+SELECT+NULL,'test'-- HTTP/2

The server returned a successful response: 

HTTP/2 200 OK

More importantly, the application displayed: 

test

This confirmed that the second column was reflected in the application's response and could therefore be used to display extracted database values.

4. Understanding the UNION Injection

The successful payload was: 

' UNION SELECT NULL,'test'--

Its components can be understood as follows:

Payload Component Purpose
' Terminates the original string value in the SQL query.
UNION SELECT Adds results from a second SQL query to the original result.
NULL Fills the first required column.
'test' Places a controllable text value in the second column.
-- Comments out the remainder of the original SQL statement.

5. Retrieving Multiple Values in One Column

The challenge was not simply to retrieve the username and password separately. The application only provided one suitable column for displaying our extracted text.

Therefore, the two database fields had to be concatenated into a single value.

The final payload was: 

GET /filter?category=Pets'+UNION+SELECT+NULL,username||':'||password+FROM+users-- HTTP/2

The SQL portion of the injection was: 

UNION SELECT NULL,username||':'||password FROM users--

6. Understanding the Concatenation

The expression: 

username||':'||password

concatenates the username, a colon separator, and the password into a single output value.

For example, if the database contained: 

username: administrator
```

password: example123
```

the expression would produce: 

administrator:example123

This allowed both database fields to be returned through the same application column.

7. Query Breakdown

' UNION SELECT NULL,username||':'||password FROM users--
Component Explanation
' Closes the application's original string context.
UNION SELECT Combines the attacker's query with the application's original query.
NULL Provides the first column required by the two-column query.
username||':'||password Combines the username and password into one displayed value.
FROM users Retrieves the data from the users table.
-- Comments out the remainder of the original SQL query.

8. Retrieved Credentials

The application returned the usernames and passwords from the users table in the following format: 

username:password

Among the returned records was the administrator account.

I used the retrieved administrator username and corresponding password to authenticate through the application's login page.

Lab Solved: The UNION injection successfully retrieved multiple database values through a single output column, allowing the administrator credentials to be obtained and used for authentication.

9. Key Lessons Learned

  • UNION-based SQL injection requires the injected SELECT statement to have the correct number of columns.
  • NULL values are useful when testing column compatibility.
  • A successful reflected string such as test identifies a useful output column.
  • Multiple database fields can be concatenated into a single output column.
  • The concatenation operator || was used in this lab to combine username and password.
  • SQL comments such as -- can be used to terminate the injected statement and neutralize the remainder of the original query.

10. Final Attack Chain

```

Identify SQL injection
↓
Determine number of columns
↓
Confirm text-compatible column
↓
Test: UNION SELECT NULL,'test'
↓
Identify the users table
↓
Concatenate username + password
↓
UNION SELECT NULL,username||':'||password FROM users--
↓
Retrieve credentials
↓
Authenticate as administrator
↓
Lab solved
```

Conclusion

This lab demonstrated how a UNION-based SQL injection can be extended beyond simply retrieving individual fields. When only one suitable output column is available, multiple database values can be concatenated into that column and returned together.

The key technique was using: 

username||':'||password

to combine the two sensitive fields into one result, which ultimately allowed the administrator credentials to be recovered and the lab to be completed.

Security takeaway: Applications should never construct SQL queries by directly concatenating user-controlled input. Parameterized queries (prepared statements) should be used to prevent SQL injection attacks.
